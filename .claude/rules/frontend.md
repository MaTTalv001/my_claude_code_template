# フロントエンド

## デザイン

- 汎用的な「AI っぽい」見た目を避け、情報設計・余白・タイポグラフィで品質を出す。新規画面や刷新では `frontend-design` を使ってよい
- **配色は下表のブランドトークンのみ**。CSS 変数（または Tailwind テーマ）として 1 か所で定義し、コンポーネントに色コードを直書きしない
- コントラストは WCAG AA 以上。キーボード操作・フォーカス表示・ラベルを欠かさない
- 社内業務ツールなので、装飾より「速く迷わず操作できる」ことを優先する（密度の高い表・明確な主要アクション・空状態/エラー状態の設計）

| トークン | 用途 | 値 |
| --- | --- | --- |
| `primary` | 主要アクション・強調 | `#XXXXXX`（仮） |
| `secondary` | 補助アクション | `#XXXXXX`（仮） |
| `background` | ページ背景 | `#XXXXXX`（仮） |
| `surface` | カード・パネル | `#XXXXXX`（仮） |
| `text` / `text-muted` | 本文 / 補助テキスト | `#XXXXXX` / `#XXXXXX`（仮） |
| `border` | 境界線 | `#XXXXXX`（仮） |
| `success` / `warning` / `error` | 状態表示 | `#XXXXXX` / `#XXXXXX` / `#XXXXXX`（仮） |

## 実装

- `any` を使わず型で表現する。サーバー状態とクライアント状態を混ぜない
- テストは Vitest + Testing Library。実装詳細ではなくユーザー操作で検証する
